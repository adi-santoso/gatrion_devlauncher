## [0.1.0] - 2026-08-14

Rilis pertama — seluruh pekerjaan P0/P1/P2 dan fitur hingga saat ini dikunci sebagai baseline `0.1.0` sebelum migrasi TypeScript dimulai. Fitur utama: manajemen project (start/stop/log streaming), terminal terintegrasi, dashboard analytics, AI agent dengan cost tracking, auto-update + notifikasi action, tema dark/light/system, i18n en/id, widget pengingat sholat, workspace backup terenkripsi, dan pipeline CI matrix 3 OS + release otomatis.

### Changed

- **Fix e2e Linux: stop process tidak lagi berubah jadi ERROR** — race khusus POSIX di `ProcessManager.handleChildExit`: `killProcessTree` di Linux mengirim SIGTERM dan resolve **sebelum** event `exit` tiba, jadi status sudah `STOPPED` saat exit datang → dianggap crash (`code !== 0`) → `failComposite` mengubahnya ke ERROR (di Windows `taskkill` menunggu proses mati, jadi aman — itu sebabnya hanya CI Ubuntu yang gagal). Exit yang tiba saat `STOPPING` **atau `STOPPED`** kini dianggap intentional. Sekalian `killProcessTree` POSIX diperkuat: ESRCH (proses sudah mati) dianggap sukses, fallback ke kill langsung, dan graceful stop menunggu ±1,5 detik lalu eskalasi SIGKILL bila masih hidup (platform injectable untuk test). +7 test (5 processTree, 2 regression race).
- **Settings "Display in" sholat kini berfungsi penuh** — sebelumnya `showIn` hanya dipakai untuk on/off global: kartu sidebar & pill topbar selalu tampil bersama, dan mati pun widget tetap muncul. Akar masalahnya `useElectronConfig` punya banyak instance (App + MainLayout) yang hanya load saat mount dan tidak pernah menerima perubahan dari instance lain. Kini `update-config` di main process **broadcast `config-updated`** ke renderer (preload `onConfigUpdated` + wrapper renderer), dan hook menyinkronkan semua instance via event `devlauncher:config-changed` + channel IPC. MainLayout juga kini memfilter per lokasi (`sidebar`/`topbar`/`both`/`off`). +4 test (sync lintas instance, push main process, preload channel).
- **Widget Pengingat Sholat dirombak total** — interval rotasi slide dinaikkan ke **10 detik** dengan animasi slide lebih lambat (450ms). — kartu sidebar & pill topbar kini menampilkan **data bergantian** (slide up/down, tiap ±5 detik): (A) **jam sekarang sampai detik** + tanggal Masehi + **tanggal Hijriah** (kalender Islam Umm al-Qura via `Intl.DateTimeFormat` bawaan, tanpa library), (B) **sholat berikutnya + countdown** seperti sebelumnya. Saat masuk waktu sholat, slide countdown diganti banner **"● Sedang Berlangsung Sholat X"** selama **10 menit** (jendela dihitung di `usePrayerTimes` → `inProgress`, termasuk rollover ke Subuh besok setelah Isya). Panel floating jadi statis lengkap: jam besar live, hijriah, banner berlangsung, jadwal 5 waktu dengan penanda benar (baris yang berlangsung diberi "● BERLANGSUNG", bukan sholat berikutnya). **Bug light mode diperbaiki**: widget sebelumnya pakai `bg-gradient to-surface` + `bg-accent-soft`/`bg-danger-soft` yang tidak punya override tema light → kartu tetap gelap; sekarang semua class theme-safe (`bg-surface`, `bg-accent/10`, `bg-danger/10`). +15 test (hook `inProgress` 5, widget 10: rotasi dengan fake timers, banner, hijriah).
- **Settings jadi tabbed layout** — halaman panjang diganti 6 tab dengan ikon: **General** (bahasa, tema, umum, notifikasi, auto-restart), **Terminal**, **Data & Backup**, **Diagnostics** (main log, crash reports, system env), **AI Agent**, **Prayer**. Semua panel tetap ter-mount (hanya disembunyikan) sehingga state di dalamnya — tail log, daftar crash dump, hasil backup, hasil pencarian kota — tidak hilang saat pindah tab. Label tab ikut i18n en/id.

Fix: eksekusi npm dipindah ke modul baru `electron/utils/npmRunner.js` yang menjalankan npm **lewat shell** (`shell: true`, PATHEXT menyelesaikan npm.cmd — pola yang sama dengan ProcessManager), dengan kill-on-timeout dan pesan error yang jelas saat spawn gagal. Bonus keamanan: nama paket divalidasi (`assertSafePackageName` — hanya karakter aman npm, metacharacter shell `; & $ ( ) …` ditolak) sehingga `npm install <name>@latest` lewat shell tetap injection-safe. +8 unit test (shell spawn, exit code 1 = sukses ala `npm outdated`, timeout membunuh child, EINVAL sinkron jadi error jelas, validasi nama).
- **History chat hilang saat membuka session lain lalu kembali** — dua akar masalah: (1) guard `sentSessionIdRef` di `AgentChat` hanya boleh menyupresi reload untuk transisi *baru-saja-dikirim*, tapi ref-nya tidak pernah dibersihkan saat user pindah ke session lain, sehingga kembali ke session itu `return` lebih awal tanpa memuat transkrip (chat tampak "new chat" kosong sampai restart); kini ref dibersihkan begitu user menavigasi ke session lain, dan (2) entry session di sidebar tidak pernah menerima `sessionPath` (hanya diketahui setelah prompt pertama) karena `handleSessionCreated` meng-skip entri yang sudah ada — kini **merge** data hasil chat ke entri list, jadi memilih ulang session memuat history dengan benar. Plus 2 regression test (reload saat kembali setelah pindah, merge session).
- **Badge token hanya muncul di session terbaru** — `touchSession` tidak pernah dipanggil dengan `tokens` (token hanya hidup di state renderer untuk session aktif, hilang saat restart). Kini ada channel IPC baru `omp-update-session-tokens` (`touchSession` menerima `tokens` numerik) dan `onTokensUsed` di AgentView mem-persist usage setiap turn selesai — badge token tampil untuk semua session dan bertahan setelah restart. Plus 1 regression test.
- **Judul aplikasi/notifikasi "electron"** — `app.setName('DevLauncher')` + `app.setAppUserModelId('com.devlauncher.desktop')` dipasang saat startup dan `BrowserWindow` diberi `title: 'DevLauncher'`, sehingga window title bar, taskbar grouping, dan atribusi notifikasi memakai nama aplikasi yang benar (di build packaged; di dev, OS tetap menampilkan nama binary electron).
- **Klik nama project di menu Agent membuka chat kosong + session implisit hilang dari list** — baris project memanggil `selectProject` yang sekaligus meng-set project terpilih (chat langsung tampil dengan state "New conversation"), dan session yang dibuat implisit oleh pesan pertama (`onSessionCreated`) hanya di-set sebagai session aktif **tanpa ditambahkan ke list sidebar**. Akibatnya: prompt pertama berjalan di session yang tidak terlihat, dan setelah pindah menu (atau klik project lagi yang me-reset session aktif) chat tidak bisa ditemukan lagi. Sekarang: (1) klik nama project **hanya expand/collapse list session** (chat terbuka saat session atau "New session" dipilih), dan (2) session yang dibuat implisit **langsung masuk list sidebar** (`handleSessionCreated` append ke `sessionsByProject`) sehingga bisa dilanjutkan kapan pun. Plus 5 regression test AgentView (expand-only, collapse, buka session, New session, session implisit muncul di list).
- **Loading session nyangkut tanpa pesan** — saat memuat transkrip session yang ada gagal (proses RPC omp tidak merespons, misal proxy mati), chat hanya menampilkan skeleton "Loading conversation…" tanpa informasi apa pun sampai timeout `_send` 120 detik. Kini: (1) operasi baca transkrip (`get_messages_page`/`get_messages`/`switch_session`) memakai timeout **30 detik** (fail fast — baca file session lokal seharusnya cepat, macet berarti RPC wedged), dan (2) kegagalan/timeout menampilkan panel error **"Couldn't load this conversation"** dengan alasan yang sudah dibersihkan dari noise wrapper IPC (`cleanIpcError`) + tombol **Retry** yang memuat ulang transkrip. Plus 5 regression test (panel error + retry berhasil, `success:false`, pembersihan pesan error).
- **App hang saat pindah menu ketika agent masih streaming** — Agent view sengaja tetap ter-mount (hidden) saat berpindah menu agar percakapan yang berjalan tidak hilang, tetapi `AgentChat` tetap me-render konten streaming setiap 30ms meskipun tidak terlihat — re-parse markdown + render ulang pohon chat yang tersembunyi ini membuat renderer jenuh dan UI menu yang sedang dibuka terasa *freeze*, sementara request omp terus berjalan sampai selesai (chat baru tampil lengkap saat kembali ke menu Agent). Sekarang prop `visible` diturunkan dari `App` → `AgentView` → `AgentChat`: saat view disembunyikan, delta streaming/thinking/tool hanya diakumulasi di buffer ref **tanpa menyentuh state React** (tidak ada re-render sama sekali), polling context/subagent juga di-skip, lalu begitu user kembali ke menu Agent seluruh konten yang ter-akumulasi di-flush sekaligus dalam satu render (dan `agent_end` tetap commit pesan final via ref). Plus regression test: delta saat hidden tidak me-render, kembali ke view langsung menampilkan seluruh balasan.
- **List markdown ber-emoji dirender sebagai paragraf lurus** — parser markdown hanya mengenali bullet `-`/`*`/`+`, sehingga baris seperti `✅ **Kekuatan** — …` dan `❌ **Kelemahan** — …` digabung jadi satu paragraf tanpa list. Kini baris yang diawali emoji bullet (`✅ ❌ ⚠️ 🔧 …`) dikenali sebagai list item dengan emoji sebagai marker yang tetap terlihat, inline markdown di dalam item tetap dirender, dan simbol biasa (`©`, `→`, dst.) tanpa variation selector tetap paragraf. Plus 3 regression test Markdown (emoji list, layout analisa lengkap heading + hr + emoji bullets, simbol biasa tidak jadi list).
- **Terminal interaktif di build produksi** — `node-pty` dipindah dari `devDependencies` ke `dependencies`; sebelumnya shell mati dengan *"node-pty is not available"* di app hasil instalasi.
- **PTY bocor (race condition)** — terminal yang dibuat setelah box ditutup kini langsung di-kill, tidak ada proses yatim.
- **Auto-scroll log tidak tersinkron** — toggle Auto-scroll di Settings kini berlaku di halaman Terminals dan Project Detail (dua arah, persist ke config).
- **Affordance shell exit** — saat shell mati (misal ketik `exit`) muncul overlay *"Shell exited with code X"* + tombol Restart.
- **Max log lines bisa 0** — input di-clamp minimal 100 agar tidak diam-diam membuang log.
- **Sidebar collapsed** — tombol Add project tidak lagi tenggelam di dark mode.
- **Topbar light mode** — tidak lagi hitam saat tema terang.
- **AgentChat safety timeout** — fallback refresh 20 detik dulu bisa menimpa generasi yang masih berjalan (menandai busy=false + refresh history di tengah streaming); sekarang hanya aktif jika tidak ada event RPC sama sekali selama 8 detik.
- **Session agent tidak bisa di-resume** — `new_session` di protokol RPC omp tidak mengembalikan path file sesi, jadi `session.sessionPath` selalu null dan klik session lama menampilkan chat kosong (baik setelah restart maupun saat berpindah session dalam satu run). Sekarang path sesi dibaca dari `get_state` setelah `new_session` dan disimpan di registry — klik session mana pun otomatis `switch_session` + `get_messages`, dan percakapan bisa dilanjutkan di sesi yang sama. Diverifikasi end-to-end dengan binary omp asli (create → restart → resume → continue).
